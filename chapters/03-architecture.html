第一部分 · 建立整体认识

系统架构与信任边界

SeeCoder 采用模块化单体：界面、可信后端和 Agent 模块随桌面应用一起运行，但通过协议和权限边界保持分工。它不需要额外数据库、Redis 或远程任务队列。

为什么选择桌面端一体化架构

编程智能体必须访问用户本地项目和本地开发工具。如果使用传统 Web 前端加远程服务器，文件需要上传，命令执行环境也与用户电脑不同；如果让浏览器直接获得 Node.js 权限，则任意渲染层漏洞都可能读取磁盘。Electron 提供了更合适的中间方案：Renderer 保持普通 Web 权限，Main 负责本地可信操作，Preload 只暴露经过约束的 IPC。

SeeCoder 分层架构
交互层 · RendererReact、任务列表、对话、审批、Diff、Terminal、Trace
通信层 · Preload类型化 IPC；不暴露 fs、child_process 或任意路径接口
可信边界 · Main窗口生命周期、工作区、密钥、设置、Session 服务与事件转发
决策层 · Agent CoreTurn 状态机、主循环、上下文、调度、审批和终止
能力层 · Model / ToolsOpenAI 兼容 SSE；文件、搜索、补丁、命令和 Git 工具
证据层 · StorageJSONL 事件、状态 JSON、Snapshot、Checkpoint 和恢复

前端与后端怎样分工

Renderer 只表达用户意图，例如“创建 Session”“开始 Turn”“允许审批”。它不自行判断工具是否完成，也不保存 API Key。Main 才是本地后端：接收 IPC 后调用 Agent Core、Storage 和 Tools，再把 AgentEvent 推给 Renderer。界面状态由事件驱动，避免前端维护一套与后台不同的业务状态机。

BrowserWindow 使用 contextIsolation: true 和 nodeIntegration: false。这意味着网页脚本即使出错，也无法直接调用 Node 文件系统。当前由于 Preload ESM 兼容原因，Electron 的 sandbox 开关未启用，所以必须准确表述为“Renderer 最小权限 + 应用层执行策略”，而不是操作系统沙箱。

核心包为什么分开

protocol定义各模块共同理解的数据：Session、Turn、Item、Event、ModelMessage、ToolCall 和 ToolResult。
agent-core只关心任务怎样运行，不直接实现 HTTP 细节和具体文件操作。
model把统一 ModelRequest 转换成 OpenAI 兼容请求，并解析 SSE 增量。
tools实现本地能力、参数校验、WorkspacePolicy、原子写入和命令管理。
storage追加写入事件，原子保存元数据与状态，提供回放和恢复。

这些包仍处于同一进程，因此没有网络序列化、服务发现和分布式事务成本。分层的目的不是追求“微服务数量”，而是让模型协议、业务状态和本地副作用可以独立测试。对当前规模，模块化单体比拆成多个后台服务更简单可靠。

数据流与控制流的区别

控制流描述“谁调用谁”：Renderer 调 Main，Main 调 Core，Core 调 Model 或 Tools。数据流描述“事实怎样传播”：用户消息成为 Item；模型增量成为 AgentEvent；工具结果进入历史；ChangeSet 更新 Ledger；事件再驱动 UI。区分两者有助于定位问题：按钮无响应通常在控制流，UI 状态错乱通常在事件数据流。

为什么不使用数据库

首版数据天然以 Session 为边界，主要写入模式是按时间追加事件。JSONL 每一行独立，便于审计、迁移和损坏尾行恢复；少量当前状态使用 JSON 原子替换；文件修改前内容直接保存为 Snapshot。引入数据库会增加 schema、迁移和原生打包成本，却不能明显改善当前规模下的查询。

这不表示 JSONL 适合无限规模。如果未来需要跨数万 Session 全文检索、多设备同步或复杂统计，数据库才有明确收益。技术选型应由实际读写模式决定，而不是由“后端必须有数据库”的习惯决定。

架构中的三个边界

权限边界位于 Main 和 Tools：模型永远不能直接操作系统。状态边界位于 Agent Core：Renderer 只消费事件，不复制主状态机。兼容边界位于 ModelProvider：Core 使用统一事件，不依赖某个模型厂商的 SSE 细节。

当前已知限制

工具 JSON Schema 在 Core 中用于提供给模型，Zod Schema 在 Tools 中用于运行时校验，两份定义存在维护同步成本。这是当前可控的技术债，不应在答辩中描述为完全单一来源。

怎样讲清楚

“SeeCoder 有前后端，但后端是 Electron Main，不是远程服务器。Renderer 无 Node 权限，Main 是唯一可信执行边界。Core、Model、Tools、Storage 用包划分职责，同时仍在一个进程运行，既容易测试，也避免分布式系统复杂度。”
