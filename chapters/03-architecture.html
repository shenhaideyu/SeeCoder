核心模块怎样分工

当前 Agent Core 已完成拆分。AgentCore 只保留对外 API 和依赖装配，具体工作交给职责单一的运行组件。

为什么要拆分

如果会话、循环、工具、审批、上下文和恢复都写在一个大类中，任何修改都可能影响整条链路。拆分后的原则很简单：每个模块只回答一个问题，AgentCore 负责把它们连接起来。

模块负责什么核心入口
AgentCore对外门面、依赖装配、事件持久化和广播startTurn、forkFrom、emit
SessionLifecycle创建、删除、分支、恢复 Sessioncreate、forkFrom、hydrate
TurnRunnerTurn 状态机和模型工具循环start、run
ToolCallExecutor一批或一次工具调用的完整管线executeBatch、execute
Context账本、证据、记忆、预算和上下文组装buildHybridContext
ChangeManager记录修改、撤销和检查点恢复record、revert、restore
SubagentRunner运行只读 Explore 和 Review 子 Agentrun

AgentCore 现在做什么

构造函数创建工具注册表、工作区策略、写入协调器、拦截器和各运行组件。公共方法只是把请求转发给正确组件。所有重要事件最后经过 emit()，统一写入 SessionStore，再通知界面。

简化结构class AgentCore {
  startTurn(...)       { return turnRunner.start(...); }
  forkFrom(...)        { return sessionLifecycle.forkFrom(...); }
  revertChangeSet(...) { return changes.revert(...); }
  resolveApproval(...) { return toolExecutor.resolveApproval(...); }
}

桌面应用的权限边界

Renderer 没有 Node.js 权限，不能直接读取文件或运行命令。Preload 只暴露明确的 IPC 方法。Electron Main 才持有 AgentCore、工作区和模型配置。模型生成的内容必须经过 Main、Core 和 Tools 才可能影响本地项目。

五个基础包

protocol所有模块共同使用的数据类型。
agent-coreAgent 状态、循环、上下文和调度。
model统一模型接口和流式响应解析。
tools本地文件、搜索、补丁、命令和 Git 能力。
storageJSONL 事件、元数据、状态和快照。
