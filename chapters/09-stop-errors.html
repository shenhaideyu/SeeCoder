模型协议与流式解析

Agent Core 只认识统一的 ModelRequest 和 ModelEvent。模型提供商负责把它们转换成 OpenAI 兼容 HTTP 请求和流式响应。

模型请求包含什么

一次请求包含消息、工具说明、模型名、温度和最大输出。工具说明使用 JSON Schema，让模型知道工具名称、用途和参数。真正执行时仍会再次使用 Zod 校验，不能只相信模型生成的数据。

流式响应有哪些事件

事件作用
textDelta一小段回复文字，立即显示到界面。
toolCallDelta工具名称或参数片段，按调用分别累积。
usage真实输入与输出 token，用于计费展示和预算校准。
retry模型层发生重试。
completed本次流正常结束，并提供结束原因。
error网络、鉴权或协议错误。

工具参数为什么需要聚合

流式 API 可能把一个 JSON 参数拆成很多片段，也可能交错返回多个工具调用。TurnRunner 按工具调用分别保存名称和参数字符串，流结束后再解析完整 JSON。这样不同工具的参数不会混在一起。

最重要的消息配对规则

合法顺序assistant: 请求调用 read_file
tool: read_file 的结果
assistant: 根据结果继续回答

工具结果不能脱离前面的工具请求。sanitizeModelMessages() 和模型层的协议归一化会删除孤立结果或不完整工具组，避免兼容 API 拒绝请求。

重试在哪里发生

临时网络错误由模型层在有限次数内重试。Agent iteration 不会因为同一次 HTTP 重试而增加。重试仍失败后，模型层发出结构化 error，TurnRunner 再把它转换为 Turn 失败状态。

真实 usage 怎样校准估算

模型返回 usage 后，TokenCalibrator 比较真实输入 token 与本地估算值，得到当前模型的比例。下一轮上下文预算使用这个比例，减少不同模型分词差异带来的误差。

协议不变式

模型输出可以分片到达，但进入工具执行前必须形成完整调用；进入下一轮模型请求前，工具请求与结果必须一一配对。
