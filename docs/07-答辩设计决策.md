# SeeCoder 答辩设计决策

## 1. 为什么不用 Agent SDK

考核要求核心逻辑自研。更重要的是，Agent SDK 会隐藏消息链、工具调度、重试、终止和恢复，评委无法判断这些能力是否真正理解。SeeCoder 只依赖原生 `fetch`、SSE 和模型 tool calling，把 Harness 保留为可阅读代码。

## 2. 为什么选择 Electron

编程 Agent 同时需要本地文件/进程能力和高密度桌面 UI。Electron Main 天然承担本机后端，React Renderer 提供对话、Diff、终端和 Trace。相比浏览器加独立服务，它不需要端口和额外认证；相比纯 CLI，它更适合演示审批、ChangeSet 和轨迹。

## 3. 为什么采用模块化单体

首版是单用户本地应用，没有跨机器扩缩容需求。拆成多个服务只会增加网络协议、生命周期和故障点。通过 packages 保持逻辑边界，已经足够独立测试和未来替换。

## 4. 为什么主 Agent 单写者

并行写 Agent 会产生文件冲突、测试相互干扰和难以归因的回滚。SeeCoder 让 Explore/Review 并发收集证据，但只有主 Agent 写入，使 ChangeSet、Checkpoint 和审批都能绑定唯一因果链。

## 5. 为什么用 JSONL 而不是数据库

事件天然追加，JSONL 易审计、易展示、易恢复损坏尾行，也没有原生数据库依赖。SQLite 查询和事务更强，但 Demo 的线程规模不足以抵消 schema migration 和打包成本。若未来多进程并发或需要复杂统计，应迁移到 SQLite。

## 6. 为什么使用事件驱动 UI

Renderer 只消费 AgentEvent，Core 不暴露内部对象。这样 UI 刷新和组件重构不会改变任务执行，真实后台状态也不会由前端猜测。代价是协议需要版本化，V2 Envelope 正是为此存在。

## 7. 为什么工具参数用 Zod

模型参数是不可信 JSON。TypeScript 类型运行时会消失，必须有实际校验。Zod 只承担 schema 校验，不参与 Agent 编排，因此不会违反禁用 Agent 框架的要求。

## 8. 为什么选择 OpenAI 兼容 Chat Completions

DeepSeek 等服务提供兼容接口，单一协议即可替换模型。直接实现 SSE 使文本、工具参数、usage 和重试都可观察。代价是不同供应商的兼容细节不完全一致，因此消息链完整性测试十分重要。

## 9. 为什么不是让模型输出 JSON 文本

自由 JSON 容易混入 Markdown、缺字段或半截输出。原生 tool calling 为调用提供 callId、工具名和参数增量；Core 再用 JSON.parse 和 Zod 校验，错误能结构化回传。

## 10. 为什么压缩不再调用另一个模型

模型摘要可能失败、花费额外 token，并可能遗漏关键事实。SeeCoder 使用 ContextLedger 加确定性历史摘录，结果可测试、可恢复。它的压缩率不一定最优，但不会把任务可靠性依赖于一次隐藏调用。

## 11. 为什么有 Plan/Guided/Auto

权限只有“全部询问”和“全部自动”会迫使用户在安全和效率间二选一。三档模式把意图分开：Plan 强制无副作用，Guided 适合演示和审查，Auto 只减少低风险重复确认。没有 Full Access，因为当前没有 OS 沙箱支撑该承诺。

## 12. 为什么使用 Checkpoint 哈希

简单恢复 before 内容可能覆盖用户在 Agent 修改后新增的编辑。afterHash 证明当前文件仍处于 Agent 留下的版本；不一致就拒绝恢复，把决定交回用户。

## 13. 为什么限制探索轮次

真实 DeepSeek 任务出现 21 轮、35 次工具调用，说明只靠 Prompt 提醒不足。第 4 轮提醒、第 7 轮硬停止是一种确定性 Harness 约束。它可能对大项目偏严格，但比无限读取更可控，可继续通过真实 Eval 调整。

## 14. 为什么 UI 默认折叠工具细节

用户首先需要知道“正在做什么、是否失败、改了什么、验证了吗”，而不是 raw JSON。主对话聚合重复探索，Trace 按轮次展示 token、耗时和失败；原始事件仍可展开，兼顾普通用户与调试者。

## 15. 如何回答当前不足

- 安全：应用层策略，不是 OS 沙箱。
- 性能：复杂真实任务功能完成，但效率门禁仍红。
- Review：只读角色已实现，Finding 结构化仍较初级。
- 规则加载：当前只读取根 AGENTS.md。
- 原子性：单文件原子，多文件没有跨文件事务。

准确说明限制比夸大能力更能证明对系统负责。
