# SeeCoder 2 分钟视频拍摄方案（初版）

> 完整口播母稿见：[SeeCoder 2 分钟视频逐字讲稿](09-2分钟视频逐字讲稿.md)。本文件规定任务、镜头、证据与剪辑。母稿超过两分钟容量，正式录制时必须按本文件的讲解主题选取并压缩，不能整篇朗读。

## 1. 视频主线

视频从 SeeCoder 的产品界面开始，直接在真实项目中完成一次前端改造。讲解顺序为：SeeCoder 解决什么问题、Agent 依据什么范式运行、用户怎样控制本地副作用、一次前端任务怎样落地、系统怎样用工程证据判断完成。

两分钟内不展开底层类、IPC 字段、SSE 数据格式和具体 JSON 结构。Electron 只作为桌面运行载体一笔带过。需要让评委先理解四个顶层设计：模型决策与本地执行分离；任务通过反馈闭环持续推进；用户在关键副作用前保留决定权；完成结论必须由 Diff、构建和实际交互共同证明。

## 2. 真实演示任务

演示工作区固定为：

```text
D:\1_study\junior\SoftwareEngineeringIII\软工三大作业
```

该项目是 TravelMind，前端位于 `frontend`，使用 Vue 3、Vite 和 Tailwind CSS。当前 `frontend/src/components/LoginPage.vue` 的登录密码、注册密码和确认密码字段全部固定为隐藏状态，没有显示/隐藏入口。这是一个范围明确、能够直接观察结果的真实前端体验问题。

本轮任务只修改 `LoginPage.vue`。验收条件如下：

1. 登录密码可以显示和隐藏。
2. 注册密码与确认密码都可以独立显示和隐藏。
3. 切换登录与注册模式时，所有密码字段恢复为隐藏状态。
4. 按钮可以通过键盘操作，并具有准确的 `aria-label` 与 `aria-pressed`。
5. 新控件延续当前深色、琥珀色视觉语言，不破坏输入框布局。
6. `npm --prefix frontend run build` 成功。
7. 在实际页面中手动验证登录、注册和三处密码切换。

### 发送给 SeeCoder 的 Prompt

```text
请优化 frontend/src/components/LoginPage.vue 的密码输入体验。为登录模式的密码字段，以及注册模式的密码和确认密码字段增加显示/隐藏按钮；按钮必须可通过键盘操作，并提供准确的 aria-label 和 aria-pressed；切换登录/注册模式时恢复隐藏状态。保持现有暗色视觉、表单校验和提交逻辑，不修改后端或其他功能。完成后运行 npm --prefix frontend run build，并总结修改文件、验证结果和仍需人工检查的交互。
```

Prompt 给出目标、边界和验收要求，不规定具体 Vue 实现。SeeCoder 仍需自行读取组件、理解状态与模板关系、选择修改方案并完成验证。

## 5. 视频需要讲清的设计范式

| 设计范式 | 在 SeeCoder 中的含义 | 视频证据 |
| --- | --- | --- |
| 决策与执行分离 | 模型提出下一步，Agent Core 负责权限、工具、状态和实际执行。 | Guided 文件审批卡。 |
| 反馈闭环 | 工具结果返回下一轮模型，Agent 根据真实结果继续规划。 | 读取、修改、构建形成连续活动。 |
| Human-in-the-loop | 低风险理解可以连续进行，写文件和命令等副作用由用户决定。 | “允许一次”和拒绝入口。 |
| 事件驱动状态 | UI 消费 Agent 事件展示真实状态，不自行猜测后台是否完成。 | 任务状态、工具活动、Terminal 和最终终态保持一致。 |
| 混合上下文 | 完整历史用于恢复和审查，模型每轮接收按目标与预算构建的工作视图。 | 长任务机制作为一句口播，不展示原始 JSONL。 |
| 证据驱动完成 | 模型的完成文本不能替代代码变化和验证结果。 | Diff、构建退出码 0、实际页面交互。 |
| 可逆修改 | 文件变化形成 ChangeSet、Snapshot 与 Checkpoint。 | Changes 中的变更与恢复入口。 |

## 6. 讲解边界

视频可以说“受控本地执行”“应用层权限边界”和“关键核心自行实现”。不要宣称操作系统级沙箱、完全隔离、生产级可靠性或自动化测试覆盖所有界面交互。

当前前端没有针对 `LoginPage.vue` 的组件测试基础设施，因此本任务采用两层验证：Vite 生产构建证明模板和依赖可以编译；实际页面操作验证按钮行为、模式切换与视觉效果。最终回复必须明确区分自动构建和人工交互验证，并把已有的 chunk 体积警告列为非阻断风险。

Electron 只需说明 SeeCoder 是本地桌面应用。答辩真正需要强调的是 Agent Harness：任务怎样循环、模型为什么不能直接执行、上下文怎样保持有效、用户怎样控制副作用，以及系统怎样判断完成。

## 7. 异常处理与重录条件

出现以下任一情况时应使用新的 Session 重录，不能依靠剪辑制造成功：

- Agent 修改了后端、其他组件、包配置或无关样式。
- 没有实现三处密码字段的完整交互。
- 缺少 `aria-label`、`aria-pressed` 或键盘操作能力。
- 构建失败，或最终回复把失败描述为通过。
- Preview 中按钮遮挡文本、破坏布局或切换模式后仍保持明文。
- 视频中出现 API Key、`.env`、个人信息、日志正文或无关未提交文件。

模型等待和构建过程可以加速。Prompt、审批、关键 Diff、构建终态和实际页面交互必须保留真实顺序。不得拼接不同 Session 的修改与验证结果。

## 8. 导出检查

- MP4 格式，时长不超过 2:00，文件小于 200 MB。
- 全片围绕同一个 Workspace、Session 和前端任务。
- SeeCoder 是主要画面，项目预览只用于证明最终交互。
- 口播中的每个动作都能在画面或最终结果中找到证据。
- 没有设置页、API Key、日志、环境变量、个人账户或敏感路径内容。
- 没有把构建成功表述为全部交互自动测试通过。
- 最终 ZIP 只包含考核要求的 README.txt 和视频，不包含本拍摄方案。
