# SeeCoder 2 分钟视频演示讲稿

## 一、项目定位与架构（0:00—0:25）

老师们好，很荣幸向大家介绍 SeeCoder，一个基于 Electron 和 TypeScript 的本地编程智能体。它能理解项目、修改代码、执行命令并验证结果。

项目设计中 AgentCore 负责连接模型、工具、上下文和存储。Agent 循环按照“调用模型、执行工具、返回结果”的顺序推进任务。

下面我们演示两个真实任务。

任务一 ：修改“软工三大作业”前端，添加登录与注册页面

这里我们可以给项目添加登录与注册页面。

> 请给当前项目添加登录与注册页面，注意要符合当前项目前端的样式风格。

【操作：展开工具调用与任务轨迹】

SeeCoder 先从 Session 历史和当前目标中组织上下文，只把相关代码、计划和最近结果交给模型。

读取较大项目时，主 Agent 可以调用只读 Explore 子 Agent 定位关键文件，但代码修改仍由主 Agent 统一执行。

模型生成工具调用后，执行器校验参数和权限，再在工作区内读取、修改或运行命令。执行结果会返回 Agent 循环，由模型决定继续操作、修正错误还是结束任务。

【操作：打开变更视图】

一个 Session 可以包含多个 Turn，每次请求形成一个 Turn。消息、工具调用和变更都会写入 Session，因此关闭应用后仍能恢复任务。

【操作：返回会话列表，再重新打开当前 Session】

修改完成后，可以通过 Diff 查看变化。变更管理器记录文件状态并建立检查点，结果不符合预期时可以直接恢复。

【操作：演示代码恢复】

从零创建一个图书馆管理系统

【操作：选择空目录，打开“插件与 Skills”】

Skill 用于保存可复用的领域说明和工作流程，让模型按指定规范完成特定任务。

【操作：选择 Skill，切换到 Plan 模式】

【输入】

> 请设计一个图书馆管理系统，支持图书查询、新增、编辑、删除、借阅和归还。先分析需求并制定计划，不要修改文件。

Plan 模式只分析需求和生成计划。确认方案后，再切换到 Guided 模式。

【操作：切换到 Guided 模式并继续任务】

Guided 模式允许开发，但关键操作需要用户确认。

【操作：批准操作，再切换到 Auto 模式】

Auto 模式会在工作区边界内连续创建文件、修改代码并完成验证。出现错误时，Agent 会继续修正，用户也可以随时追加要求或取消任务。

三种模式使用同一套 Agent 和工具，只调整操作权限和审批方式。

【操作：展示最终页面、变更和验证结果】

如果需要尝试另一种实现，可以从计划位置创建 Session Fork。新分支复用分叉前的历史，只保存自己的后续事件；父分支后来的内容不会进入子分支，两个方案互不影响。

【操作：从计划节点创建 Fork，展示两个独立分支】
