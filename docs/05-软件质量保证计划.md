# SeeCoder 软件质量保证计划

## 1. 质量目标

SeeCoder 的质量排序为：数据与权限安全 > 状态正确 > 任务成功率 > 可理解性 > 性能 > 视觉润色。不能为了演示速度牺牲越界检查、取消、回滚或密钥保护。

## 2. 缺陷等级

| 等级 | 定义 | 示例 | 处理 |
| --- | --- | --- | --- |
| P0 | 数据损坏、越权、任务无法终止、状态错误 | 越界写、取消后继续执行、失败显示完成 | 立即停止发布并修复 |
| P1 | 严重影响主流程或成功率 | tool 消息链 400、无限探索、恢复错误 | 优先于新功能 |
| P2 | 信息层级、维护性或次要性能 | Trace 过密、组件重复 | 在核心稳定后修复 |
| P3 | 低收益视觉细节 | 极小间距差异 | 不增加复杂度时处理 |

## 3. 变更流程

```text
可观察问题
→ 保存证据和复现路径
→ 定位根因
→ 最小正确修复
→ 增加回归测试
→ 运行相关测试
→ 真实 UI 或真实模型复验
→ 独立里程碑提交
```

禁止仅凭“架构感觉不好”大规模重写。协议或安全边界变化必须先更新规格和文档。

## 4. 分支与提交

- `main` 保存可发布版本，`develop` 保存已验证里程碑。
- 使用 Conventional Commits。
- 不改写已经推送的历史，不强推，不伪造提交时间。
- 每个提交聚焦一个可说明的根因。
- 截止时间后停止远端 Push。

## 5. 代码门禁

每次源码变更至少执行：

```text
pnpm lint
pnpm typecheck
相关单元/集成测试
```

发布候选执行完整测试、构建、E2E、示例项目测试、敏感信息扫描和依赖检查。核心包不得引入被禁止的 Agent 框架。

## 6. 评审检查表

- 是否扩大文件或命令权限？
- 是否改变 Thread/Turn/Event 语义？
- Tool Result 是否始终回给模型？
- 失败能否形成终态？
- AbortSignal 是否传递到新增异步操作？
- 是否可能重放副作用？
- 是否把大输出或敏感内容写入日志？
- UI 是否只依赖公开事件？
- 是否有与根因对应的回归测试？

## 7. 发布检查

- 工作树和远端分支状态明确。
- README.txt 不超过考核限制且地址真实。
- 仓库、历史、日志样例中无密钥。
- 两分钟演示连续成功。
- 明确展示应用层安全策略，不夸大为 OS 沙箱。
- 记录真实评测中仍未达标的性能指标。

## 8. 质量度量

- 自动测试通过数和失败类型。
- 真实任务完成率。
- 每 Turn 模型迭代与工具调用数。
- 重复工具签名和失败工具数。
- 单次最大输入 token。
- 取消到终态延迟及孤儿子进程数量。

这些指标用于发现回归，不制造虚假百分比进度或单一“Agent 分数”。
