# SeeCoder 需求分析

## 目标

SeeCoder 为 Windows 开发者提供一个可审计的本地编程智能体：模型提出行动，主进程在工作区内读取文件、搜索代码、应用补丁、运行验证，用户能在每个高风险动作前介入。

## 角色与场景

- 开发者：选择项目、提出任务、审批动作、查看 Diff 和测试证据。
- 主 Agent：维护一个 Turn 的状态并负责唯一写入。
- Explore/Review 子 Agent：独立上下文只读分析，返回证据和建议。

## 功能需求

| 编号 | 需求 | 验收 |
| --- | --- | --- |
| FR-01 | 新建/恢复 workspace thread | 重启后可恢复事件和状态 |
| FR-02 | OpenAI 兼容 SSE/tool calling | fake provider 可驱动至少两轮工具循环 |
| FR-03 | 文件读取、搜索、补丁、写入 | 越界路径拒绝，补丁失败不半写入 |
| FR-04 | 命令执行 | 实时 stdout/stderr、超时、取消、输出上限 |
| FR-05 | Guided/Auto 权限 | Guided 逐次审批，Auto 仅低风险工作区动作自动化 |
| FR-06 | 上下文管理 | 70% 预算触发压缩且保留目标、计划、变更、测试 |
| FR-07 | 子 Agent | Explore/Review 独立上下文，最多并发 2 个，不可嵌套 |
| FR-08 | 轨迹和证据 | UI 显示计划、工具、终端、Diff、子 Agent、测试结果 |
| FR-09 | Electron UI | 1280×800 无遮挡，Renderer 无 Node 权限 |

## 非功能需求

- 密钥不入库；所有执行事件追加写入 JSONL。
- 失败、取消、拒绝和达到限制必须可恢复且有明确提示。
- 首版不实现 MCP、远程执行、Full Access、并行写 Worktree。

## 2.0 扩展验收

- FR-10：提供 Plan/Guided/Auto 三档模式；Plan 运行期间不得产生写入或命令副作用。
- FR-11：提供 Follow-up、ask_user、Checkpoint、撤销、Review Finding、文本/图片附件和局部 Git 操作。
- FR-12：左侧导航、顶栏、Composer、Changes/Files/Terminal/Preview/Trace 及设置页所有可见按钮均有真实行为或明确配置提示。
- FR-13：V2 事件包含 `version/id/seq/type/threadId/timestamp/payload`，V1 JSONL 可读取，重启后恢复计划、变更和 Checkpoint。
