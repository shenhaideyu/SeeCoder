# SeeCoder 测试计划与测试用例

## 1. 测试目标

测试重点不是确认按钮存在，而是证明不可信模型输出经过 Harness 后仍满足状态、权限、幂等和恢复约束。测试按“纯函数 → 模块 → 垂直闭环 → 真实模型”分层。

## 2. 测试层次

| 层次 | 技术 | 覆盖对象 | 失败含义 |
| --- | --- | --- | --- |
| 单元 | Vitest / Node test | Parser、Core、Policy、Storage | 局部设计不满足契约 |
| 集成 | Vitest + 临时目录/Git + Fake Provider | 多轮工具循环和文件副作用 | 模块组合存在缺陷 |
| Electron E2E | Playwright Electron | IPC、页面、终端和恢复 | 用户主流程不可用 |
| 真实 Prompt Eval | DeepSeek 会话 JSONL | 成功、证据与效率预算 | Harness 在真实模型上退化 |

## 3. Model 测试

- SSE 数据被任意拆分时仍可重组。
- 文本 Delta 顺序不变。
- 同一 tool call 的 name 和 arguments 可跨多个 chunk 到达。
- 多个 call 通过 index 绑定独立 callId。
- usage 和 finish reason 正确转换。
- 429/502/503/504 最多重试 3 次。
- AbortSignal 中止读取和退避等待。
- Assistant tool calls 序列化为 OpenAI `tool_calls`，Tool 消息带 `tool_call_id`。

## 4. Agent Core 测试矩阵

| 场景 | 关键断言 |
| --- | --- |
| 读取→修改→验证→完成 | ToolResult 回填后模型能进入下一轮 |
| Guided 写入 | 未批准前文件不变，批准后继续 |
| Plan 写入 | 返回 `plan_read_only`，没有副作用 |
| 重复 callId | 第二次返回缓存结果，不重复写入 |
| 跨 Turn 同 callId | 不共享缓存 |
| 取消审批等待 | Turn 终止，无僵尸 Promise |
| 输出 `length` | 不标记完成，注入恢复提示 |
| 连续截断 | 三次后 `output_limit` 失败 |
| 探索预算 | 第 7 轮后读取受控停止，行动仍允许 |
| 自动压缩 | 保留完整 assistant/tool 调用组 |
| 旧历史孤立工具消息 | hydration 时删除非法链 |
| 应用中断 | 未终结 Turn 只补写一次 `interrupted` |
| Delta 持久化 | 实时监听可见，但 JSONL 不保存 Delta |
| Checkpoint 冲突 | 当前哈希变化时拒绝恢复 |

## 5. Tools 测试矩阵

- `..`、绝对路径和符号链接越界。
- `.env`、私钥、credential、token 文件过滤；`.env.example` 允许。
- `read_file` 最多 400 行。
- `read_files` 最多 30 个文件并支持局部错误。
- `search_text` 的 rg 路径与 Node 回退。
- unified diff 成功、格式错误、上下文冲突和模糊匹配。
- 单文件原子写入。
- 命令 stdout/stderr、非零退出、超时和取消。
- PowerShell 进程树通过 `taskkill /t /f` 终止。
- Guided/Auto 风险矩阵和 `commandRisk`。
- Git Diff 在父仓库中的工作区范围限制。

## 6. E2E 主流程

Playwright 启动构建后的真实 Electron，而不是只搜索源码字符串：

1. 使用临时 `userData` 和临时 workspace。
2. 验证窗口标题和核心入口。
3. 新建任务并验证菜单事件也能创建任务。
4. 切换 Plan，验证权限文案。
5. 1000×720 下检查 Composer、检查器按钮和横向溢出。
6. Files 面板显示 `.env.example`，不显示 `.env`。
7. Terminal 真实执行目录命令并显示输出。
8. 关闭重启后验证模式恢复。

## 7. 真实 Prompt Eval

评测目录保存自然语言任务目录，不使用“必须调用某工具 N 次”的刻意提示。指标包括：

- 是否找到完全匹配的真实轨迹。
- 终态是否 `completed`。
- 模型迭代、工具调用、失败工具、重复调用。
- 单次最大输入 token、最终答案长度、副作用数量。
- 复杂任务是否包含 `apply_patch/write_file/run_command/finish` 证据。

控制流信号 `exploration_budget_exhausted` 不计为工具故障，否则 Harness 主动收敛会被误判成运行错误。

当前真实结果：简单任务 4 轮、5 次工具；中等任务 6 轮、13 次工具；复杂任务功能完成但 21 轮、35 次工具、75,485 最大输入 token，尚未达到效率 SLA。这一红灯应保留，不能通过放宽门槛掩盖。

## 8. 验证命令

```powershell
pnpm lint
pnpm typecheck
pnpm test:unit
pnpm test:integration
pnpm test:eval:unit
pnpm test:eval:real
pnpm test:e2e
pnpm build
node --test examples/task-board/tests/task-board.test.mjs
```

`test:eval:real` 依赖本机真实会话，不应作为无会话 CI 的唯一阻断条件；其结果用于产品质量评估。

## 9. 通过标准

- Lint、Typecheck、Unit、Integration、E2E 和 Build 必须通过。
- 越界、Plan 副作用、取消失效、重复写入和状态错乱均为零容忍。
- 真实复杂任务必须有修改与测试证据；效率指标可作为明确的待优化项，但不得伪报通过。

## 10. 测试限制

- 当前没有长期内存压力和数百 Thread 的性能基准。
- E2E 主要覆盖主入口，审批卡的所有分支仍更多依赖 Core 集成测试。
- 模型供应商兼容差异无法由 Fake Provider 完全覆盖。
