# 技术选型与替代方案比较

## 1. 选择标准

技术选择按以下顺序判断：满足考核自研要求、保护本地环境、可测试可解释、适合两分钟演示、实现成本可控。不是追求组件数量或流行度。

## 2. Electron + React + TypeScript

| 方案 | 优点 | 本项目判断 |
| --- | --- | --- |
| Electron | 本地能力与桌面 UI 同一产品，生态成熟 | 采用 |
| 浏览器 + 本地服务 | UI 熟悉，但需端口、鉴权和服务生命周期 | 当前不采用 |
| Tauri | 体积更小、系统边界强 | 引入 Rust 与跨语言调试，时间成本更高 |
| 纯 CLI | 实现小、资源低 | 难展示 Diff、审批、Trace 和工作区管理 |

TypeScript 让协议、Main、Preload 和 Renderer 共享类型。React 适合事件驱动的复杂工作台，Zustand 只管理 UI 派生状态，不承担 Agent 编排。

## 3. 模块化单体 vs 微服务

模块化单体具有一个部署单元，packages 保持职责分离。微服务适合多用户、独立扩缩容和故障隔离，但本地单用户 Agent 使用它会增加 RPC、身份和部署成本。当前 Main 就是后端，并非“没有后端”。

## 4. 原生 Harness vs Agent 框架

Agent 框架能快速获得工具循环和记忆，但违反考核要求，并隐藏最需要答辩的逻辑。自研 Harness 可以精确控制消息顺序、审批、幂等、终止和恢复，代价是必须自行覆盖边界测试。

## 5. OpenAI 兼容协议 vs 多供应商原生协议

单一兼容协议能接入 OpenAI、DeepSeek 和兼容网关，减少首版范围。首发同时实现 Anthropic/Responses 会显著扩大消息和工具语义矩阵。正确扩展方式是新增 ModelProvider，不改变 Core。

## 6. 原生 fetch vs 模型 SDK

fetch 已提供流、取消和 HTTP。模型 SDK 可能简化序列化，但会引入版本耦合并遮蔽 SSE 细节。直接实现更适合展示底层原理，也让 Fake Provider 完全独立。

## 7. Tool Calling vs 解析 Markdown/JSON

原生 tool calling 提供 callId、函数名和参数增量。解析 Markdown 代码块无法可靠区分解释和动作，也没有幂等标识；要求模型输出单个 JSON 又难支持文本与多工具并存。因此选择原生工具协议，再叠加 JSON 和 Zod 两层校验。

## 8. Zod vs 仅 TypeScript/JSON Schema

TypeScript 在运行时消失，JSON Schema 主要给模型描述。Zod 的 `safeParse` 适合执行边界并产生结构化错误。它没有参与规划或循环，因此只是验证库。

## 9. JSONL vs SQLite

| 属性 | JSONL | SQLite |
| --- | --- | --- |
| 追加审计 | 天然 | 需要表设计 |
| 人工检查 | 简单 | 需工具 |
| 损坏尾行恢复 | 可逐行跳过 | 依赖事务/WAL |
| 查询与索引 | 弱 | 强 |
| 多进程写 | 弱 | 强 |
| 打包依赖 | 无原生依赖 | 可能需要原生模块 |

Demo 选择 JSONL。若 Thread 数量、搜索或并发显著增长，SQLite 是合理迁移方向。

## 10. 确定性压缩 vs 模型摘要/向量记忆

确定性压缩便宜、稳定、可测试，ContextLedger 保证关键状态。模型摘要语义更强但会引入额外失败和成本；向量记忆适合大知识库，但不能解决合法 tool 消息链。首版先解决正确性，未来可把语义检索作为可选 Context Source。

## 11. 单写者 vs 并行写 Agent

单写者使审批、Diff、测试和恢复有唯一责任链。并行写可提升吞吐，但需要 Worktree、合并策略、冲突解决和重复测试，超出 Demo 范围。只读子 Agent 已保留并行分析价值。

## 12. 应用层策略 vs OS 沙箱

路径策略和审批实现快、可解释，能防止常见越界，但无法完全约束任意 Shell。容器、Windows Sandbox 或受限 Token 能提供更强隔离，却增加环境准备和跨平台复杂度。SeeCoder 明确选择应用层策略并诚实披露残余风险，不把它包装成系统沙箱。

## 13. 原子文件 + Checkpoint vs Git 自动提交

Git 提交可以恢复，但会污染用户历史，也不适用于非 Git 工作区。ChangeSet/Checkpoint 独立于 Git，用户仍可查看和撤销。Git 按钮作为显式用户动作保留，而不是每次修改自动提交。

## 14. SSE vs WebSocket

模型响应是服务器单向流，SSE over fetch 足够且与兼容 API 一致。WebSocket 适合双向实时协议，但会增加连接状态和重连语义。Renderer 与 Main 使用 Electron IPC，不需要再引入 WebSocket。

## 15. Monaco/xterm.js

Monaco 提供成熟 Diff 和代码预览；xterm.js 提供 ANSI 终端显示。命令本身仍由 Main 的受控非 PTY runner 执行。自行实现编辑器/终端渲染收益低且容易出现可访问性和性能问题。

## 16. 何时应改变当前选择

- 多用户远程执行：独立服务 + 队列 + OS 沙箱。
- 数万会话和复杂查询：SQLite/PostgreSQL。
- 百万行仓库语义检索：增量索引/Embedding。
- 多 Agent 并行开发：Worktree + 合并调度。
- 交互式终端：受控 PTY 与会话权限模型。

这些是触发条件，不是首版必须提前建设的抽象。
