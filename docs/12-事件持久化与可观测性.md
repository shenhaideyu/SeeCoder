# 事件持久化与可观测性

## 1. 事件是运行事实

AgentEvent 回答“发生了什么”，而不是保存 Core 的任意对象快照。事件包括 Thread/Turn、消息、模型请求、工具、审批、变更、子 Agent、压缩、Review 和终态。

## 2. V2 Envelope

```ts
interface AgentEventEnvelope<T> {
  version: 2;
  id: string;
  seq: number;
  type: string;
  threadId: string;
  turnId?: string;
  timestamp: string;
  payload: T;
}
```

`threadId` 必须显式存在，不能依赖事件内部字段推导，否则多个任务同时更新时 UI 容易串线。`seq` 提供线程内顺序，`id` 提供事件身份。

当前持久记录同时保留 `event` 与 `payload`，这是 V1/V2 兼容策略，不是两个事件。读取优先兼容已有 event，也能读取只有 payload 的 V2。

## 3. 文件布局

```text
%APPDATA%/SeeCoder/
├─ config/settings.json
├─ schedules.json
├─ logs/main.log
└─ sessions-data/
   ├─ sessions/<thread-id>/
   │  ├─ meta.json
   │  ├─ state.json
   │  └─ events.jsonl
   └─ snapshots/<thread-id>/<change-set-id>/
```

meta 和 state 使用临时文件加 rename；events 使用 appendFile；snapshot 保存修改前文本或缺失标记。

## 4. 为什么选择追加式 JSONL

- 每个事件单独一行，易人工审计。
- 崩溃通常只影响尾行，读取时可跳过损坏行。
- 无数据库原生模块和 migration。
- 轨迹可以直接用于真实 Prompt Eval。

代价是查询需要扫描文件、并发写保障有限、历史持续增长。它适合单机 Demo，不是多租户后端方案。

## 5. V1 兼容与损坏恢复

`readEvents` 对每行独立 JSON.parse：存在 `event` 就按旧/兼容记录读取，只有 `payload` 则转换为 SessionEvent。无法解析的行跳过，其他事件继续恢复。读取后以最高 seq 初始化内存序号。

这种策略优先可用性。缺点是中间损坏行也会静默跳过，因此生产系统应增加校验和与告警；当前至少保证尾行损坏不会摧毁全部会话。

## 6. 状态恢复

meta 恢复 Thread 属性；state 恢复 ContextLedger；Item 重建模型消息；事件恢复 ChangeSet、Checkpoint、计划和 UI 时间线。未终结 Turn 被转换为 `interrupted`，而不是假装仍在后台运行。

## 7. 实时事件与持久事件

大多数事件同时持久化并推给 Renderer。例外是 `message.delta`：它只实时推送，最终文本通过 `message.completed` 保存。`tool.output` 会作为实时事件进入日志/时间线，模型使用最终结构化 ToolResult。

## 8. Main 结构化日志

`main.log` 采用单行：

```text
timestamp [LEVEL] message {json details}
```

关键字段包括 `threadId/turnId/callId/tool/iteration/durationMs/inputTokens/outputTokens/retries/finishReason/error`。日志队列串行 append，避免并发行交错。

不记录 API Key、完整文件内容和完整命令输出。tool.output 日志只记录 stream 和字节数。探索预算是受控状态，按 INFO 而非 WARN 记录。

## 9. 一次调用链如何追踪

```text
turn.started(threadId, turnId)
model.requested(iteration)
model.completed(duration, tokens, retries)
tool.requested(callId, tool)
approval.requested/resolved
tool.output(callId, stream, bytes)
tool.completed(callId, ok, duration, error)
changes.created(changeSet)
turn.completed/failed/cancelled
```

通过 threadId 找任务，通过 turnId 找本轮，通过 callId 关联工具输出和结果。

## 10. UI Trace

普通 UI 不平铺全部事件。Trace 将事件按模型轮次分为阶段卡片，显示工具摘要、失败数、token 和耗时；流式碎片默认隐藏，原始事件仍在会话记录中。主对话进一步把连续只读工具聚合为“探索项目 × N”。

这是渐进披露：默认回答用户当前决策所需信息，调试者再展开底层细节。

## 11. 通知与计划任务

Turn 完成且窗口不聚焦时 Main 可发系统通知。计划任务由应用内 60 秒循环检查，仅处理当前 workspace，固定以 Plan 模式启动，并用 runningSchedules 防止同一计划重入。

## 12. 隐私边界

日志与 JSONL 位于用户 AppData，不进入仓库，但仍可能包含任务文本、路径、工具参数和代码片段。它们不应作为公开附件直接上传。导出前应由用户检查和脱敏。

## 13. 当前限制

- 没有日志轮转和会话归档。
- JSONL 没有校验和、文件锁或事务索引。
- seq 是线程内逻辑序号，不是跨线程全局时钟。
- Trace 阶段由事件顺序派生，不是分布式 tracing 系统。
- 当前没有自动性能采样或长期内存指标。
