SeeCoder 是一个面向本地项目的可视化编程智能体。它关注的不是让模型一次生成一段看似正确的代码，而是把真实编程任务组织成可以持续执行、可以被用户理解、也可以被工程证据验证的完整过程。用户只需要描述目标，SeeCoder 会围绕这个目标读取项目、整理计划、修改文件、运行命令、检查结果，并在获得新信息后继续调整方案。对不熟悉代码库的用户来说，计划、工具活动、文件变化和验证结果都能在同一界面中看到，因此用户不需要预先掌握全部实现细节，也能理解任务目前进行到了哪里。

整个系统最重要的设计原则是把模型决策与本地执行分开。大语言模型擅长理解需求、分析代码和提出下一步，但它的输出不能直接等同于真实操作。SeeCoder Core 才是任务的控制者，它负责维护状态、构建上下文、解析模型输出、检查工具参数、执行权限策略并调用本地工具。模型可以建议读取哪个文件、怎样修改代码或运行什么命令，却不能绕过 Core 直接接触文件系统。SeeCoder 是本地桌面应用，界面负责交互和展示，真正的模型调用与本地执行集中在可信核心中。

一次任务按照固定的反馈闭环运行。用户提交目标后，Core 先根据当前 Session、项目规则和已有证据构建工作视图，再把这个视图和可用工具发送给模型。模型返回自然语言或者结构化工具请求，Core 完成解析、校验和必要审批后执行工具，并把真实结果重新交给模型。模型随后依据新的代码、命令输出或错误信息继续规划。这个循环会不断重复，直到任务已经得到验证、用户主动取消、出现不可恢复错误，或者达到明确的迭代限制。完成状态由系统规则判断，不以模型简单说一句“已经完成”为准。

长任务能否稳定运行，关键在于历史记录和模型上下文必须分开管理。SeeCoder 会保留完整的 Session 事件，用于界面展示、重启恢复和事后审查；模型每一轮只接收 ContextBuilder 根据预算生成的有限工作视图。这个视图优先保留当前目标、约束、计划、相关代码证据、最新修改、未解决错误和最近完整工具交互。重复文件读取会通过内容哈希复用证据，冗长命令输出会压缩为保留退出码和关键诊断的 Observation，较早对话则按需摘要或检索。这样既不删除原始历史，也避免把全部内容反复发送给模型。

工具系统承担了从模型建议到本地能力之间的边界。每个工具都有明确名称、参数结构、副作用类型和风险等级。模型提出工具请求后，Core 会检查工具是否存在、参数能否通过运行时校验、当前权限模式是否允许、目标路径是否仍在工作区内，以及是否需要用户批准。文件读取、搜索、补丁、命令和 Git 操作都经过同一条门禁链。工具执行产生的完整结果会进入事件记录，而下一轮模型只接收适合推理的紧凑观察。模型负责选择动作，程序负责决定动作能不能执行以及怎样可靠执行。

SeeCoder 提供 Plan、Guided 和 Auto 三种执行模式。Plan 只允许读取、搜索和分析，适合先理解项目；Guided 会在写文件和运行命令前逐次询问用户，适合需要明确控制的真实项目；Auto 可以自动执行工作区内的低风险操作，但高风险行为仍受限制。文件写入会形成 Diff、ChangeSet 和 Checkpoint，用户能够查看具体增删行，也可以恢复修改。命令支持超时和取消，取消信号会继续传递到模型请求和受控子进程。这里采用的是应用层安全边界，不是操作系统级沙箱。

系统使用事件驱动方式统一后台事实与界面状态。一次用户请求称为一个 Turn，多个 Turn 组成可以持续追问的 Session。任务开始、模型请求、工具调用、审批、文件变化、验证和终态都会形成顺序事件。界面根据这些事件展示进度，不需要自己猜测后台是否仍在运行。应用重启后，Storage 可以通过元数据、状态快照和事件记录恢复已经发生的事实；未完成任务会标记为中断，历史工具副作用不会被自动重放。这种设计让运行过程既可观察，也便于定位失败发生在哪一步。

下面演示 SeeCoder 直接修改“软工三大作业”中的 TravelMind 前端。当前登录和注册页面的密码字段只能保持隐藏，用户输入错误时很难核对内容，也没有显示或隐藏密码的控制。我的目标是让 SeeCoder 在不改动后端和其他功能的前提下，为登录密码、注册密码和确认密码增加显示隐藏按钮，同时支持键盘操作，提供准确的无障碍状态，并保持页面原有的深色与琥珀色视觉风格。这项任务同时涉及现有组件理解、交互状态设计、模板修改、视觉一致性和实际验证，能够代表真实的前端维护场景。

我把工作区切换到软工三大作业，新建独立 Session，并选择 Guided 模式。发送任务后，SeeCoder 先搜索目标组件，读取现有脚本、表单结构和样式，确认密码字段怎样在登录与注册模式之间复用。随后它形成简短计划，决定增加独立的可见状态、动态输入类型和按钮属性，并在模式切换时重置状态。这个阶段只产生读取和分析，不直接修改代码。用户能够从工具活动中看到它读取了哪些文件、当前准备做什么，以及修改范围是否仍然符合最初要求。

模型提出文件修改后，SeeCoder 展示审批卡和 Diff。我会先检查目标是否只有 LoginPage.vue，再确认修改同时覆盖登录密码、注册密码与确认密码，没有破坏原来的校验和提交逻辑。只有在我选择允许之后，Core 才会真正写入文件。写入完成后，Changes 面板展示本轮产生的增删行，并记录可恢复节点。这个过程体现了 Human-in-the-loop 的设计：模型负责生成方案，系统负责约束执行，用户对真实副作用保留最终决定权。

代码修改完成后，SeeCoder 运行前端生产构建。构建成功和退出码为零可以证明 Vue 模板、依赖和打包流程没有被破坏，但它不能单独证明交互体验正确。因此我还会打开 TravelMind 的实际页面，分别检查登录密码、注册密码和确认密码的显示隐藏效果，使用键盘聚焦并触发按钮，再切换登录和注册模式确认密码重新隐藏。自动构建与人工交互检查解决的是不同问题，只有两类证据都成立，才能说明这次前端任务达到了预期。

最终回复会汇总用户目标、根因或设计判断、修改文件、自动验证、人工检查和仍然存在的风险。SeeCoder 不把模型最后一段话当作唯一交付物，而是把计划、审批、Diff、命令结果、预览和完成摘要连接成可以追溯的执行链。项目没有使用现成 Agent 框架，主循环、混合上下文、流式模型输出解析、工具定义与本地执行、终止条件、错误处理和 Session 恢复均由项目自行实现。它的核心价值不是追求完全无人干预，而是让模型能力进入一个可观察、可控制、可恢复并能够用工程证据证明完成的本地编程系统。
